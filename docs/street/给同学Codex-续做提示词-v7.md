你接手的是《过早旧影》武汉美食文化老街项目。请在交接代码上继续实现和验收剩余工作，不要从空项目重写，也不要只给我建议或停在计划。先读文档、运行当前效果、保留已有成果，然后按下列顺序完成。每完成一家店就实际预览、修复并保存可运行版本，再做下一家。

## 一、已经定下的产品方向

这是一个能自由逛店的武汉早餐文化体验：好看的插画封面 → 街道地图 → 用户点击店铺圆点 → 以第一人称沿街走过去 → 看食物和店主、阅读简短文化介绍 → 把喜欢的食物放进左侧“我的过早”食篮 → 随时换店或切换昔日/今日。

用户明确不要强制的故事路线，不要依次完成第一站才能进入第二站，不要读完历史才能收藏。地图是这一条老街的空间示意，不是以前的中国省份地图。食篮用于个人收藏和记忆，没有付款、价格、库存或真实下单。

最终美术是细线淡彩的立体绘本：清楚的暖灰线条、青灰瓦、粉蓝墙、暖木色、豆绿植物、剖开的室内、细致生活物件、柔和清晨光影。用层层纸片与有厚度的简单几何搭三维空间，能走近、产生遮挡与投影。不要退回纯色低模、摄影风整图贴墙或油亮的写实渲染。参考图里的水乡、火锅馆等只是画风，不要原样移植成武汉历史。

保留今昔对比。昔日的气氛以 1980 年代武汉生活意象为设计方向，但街巷与人物是虚构艺术创作；不能把生成图写成真实历史照片或考证完成的复原。今日也应有生活延续感，不要只换一个全屏滤镜。

做面小游戏、拍照 AI 复原、在线 AI 对话不是本次剩余工作的范围，不要自行添加后端、密钥、付费服务或支付功能。

## 四、按顺序完成剩余工作

### 阶段 A：先把可复用的单店接入理顺

检查 `AtelierScene.ts`、`SceneExtension.ts`、`PaperWorkshop.ts`、`MorningStreet.ts` 和 `FoodStalls.ts`。在保留林记现状的前提下，提取小而清楚的店铺模块接口：挂载到 socket、更新动态、按年代切换、提供热点/特写锚点、销毁资源。全街复用一个 renderer 和场景，不要每家创建一个 WebGL canvas。

不要把整个林记引擎复制五份，也不要先做大范围重构后长时间没有可运行页面。优先用一家豆皮铺验证接口，再复用到其他店。

### 阶段 B：将豆皮和面窝做到林记同等完成度

每家补齐以下交付：

- 昔日与今日的店内墙面、陈设、招牌、工具和至少一项具体生活变化。两套背景保持同一空间结构，能通过真实纸墙转动过渡。
- 独立人物：透明身体纸偶，至少五种清楚的嘴型加独立眨眼；连续变化自然，脸部位置、眼睛与下巴不漂移。静止时回到自然表情。
- 真正分层的柜台、后墙、货架、器物和装饰。食物近看能辨认材料/层次，光影与室内一致；禁止只有一张背景图和几个粗方块。
- 豆皮体现分块、糯米和外皮；面窝体现厚边薄心与铁勺。表现细节要符合可靠资料，不能画成无关甜甜圈或西式糕点。
- 食物持续轻微热气，背面与侧看不露方形透明贴片；在场景旋转、店铺旋转和翻墙时坐标正确，不穿碗、锅或台面。
- 一件可近看旧物、两到三组可自由选择的话题，以及一个明确的今昔对照点。
- 所有内容接入地图、第一人称目标、阅读卡片、食篮和下载手册，手机也可操作。

### 阶段 D：扩展地图、食篮与整街今昔

扩店时同时更新 `exploreContent.ts`、`exploreState.ts`、共享食物类型/资料表和测试。当前 `FoodNote` 来自 `tourContent.ts`，不要只在 JSX 里加一项，导致类型、存档校验、下载和食篮迁移不认识新食物。可逐步提取专用的数据表，但要保留旧存档兼容。

地图圆点由世界坐标投影，不能写死百分比坐标。增加地点后，桌面与手机都必须可点到所有地点；采用短标签、展开列表或合理的遮挡处理解决重叠，不能用隐藏地点代替解决。

第一人称以约 Y=2.45 的眼高在街道中走近，拐弯自然，不从屋顶飞过去，不穿墙。柜台高度和注视点配合，让用户看得清食物。维持“地图选店—走近—自由看—回地图”的任意顺序，不能加回站点锁。

食物到访后即可保存，去重、移除、回看、刷新恢复、下载都要适配新店。原故事、旧 v6 导览和新 v7 存档不能互相覆盖；当前新键为 `wuhan-breakfast-story.explore.v1`，修改结构须显式迁移，不能清空用户数据。

整街今昔先设计有依据的差异清单，再实施：门窗维护、招牌制作、器物、出行/购物方式和人物服饰可以变化，空间和故事保持关联。共享年代状态与翻面进度； UI 颜色/文案、店内资产与街角陈设在正确时机切换。不要点击即瞬切，不要出现半翻转时两面内容同在、人物重复、蒸汽穿墙。暂停环境动态时，主动点击今昔仍应完成翻转。

### 阶段 E：统一品质与性能后再交付

继续用暖日出方向光、长而柔和的阴影、叶影、少量热气与微尘表达清晨。不能靠加亮泛黄洗掉线条。地板保留石板接缝、磨损和湿润差异，墙面保留修补、露砖和生活痕迹，避免重复贴图太明显。

当前截图精度较高，但还有性能优化余地。记录实际 renderer draw calls、帧时间和显存代理信息；先处理重复材质/几何、无必要轮廓线、透明层 overdraw、阴影范围与像素比，再增加密度。静态物件可批处理，动画组需保留独立。提供低性能设备可用的画质选项，保持 UI、圆点和食篮始终可用。

在桌面和手机竖屏检查；不要把 headless 桌面上的手机视口截图当成实体手机性能结果。若有实体手机再测，并准确记录设备。没有条件的部分明确写未验证。

## 五、素材制作与文化资料提取方法

先用现有 `storybook` 资产保持一致。确需新素材时使用你环境中可用的图像生成/编辑工具，保存完整提示词、生成原图、用途、运行时导出与文件对应关系。产品运行时加载本地静态资产，不要求用户提供生成服务密钥。

生成时固定画风、光向、透视、角色服饰和构图。分别生成干净后墙、人物透明纸偶、前景器具与植物；为会被抠出的部分预留完整轮廓。制作表情必须基于同一张角色做局部变化，检查帧间眼睛、鼻子、头发与衣领对齐。透明图必须检查 alpha，不能把棋盘格或白边画进图里。招牌文字用网页/纹理排版保证可读，不依赖生成图写汉字。

当前提示词和素材清单是复用起点，不要求生硬照抄。如果当前工具不能生成或处理素材，说明实际缺失能力与受影响项，保持程序可运行；不能把临时方块当最终精细美术，也不能假装已生成不存在的文件。

文化研究优先使用武汉/湖北政府、文旅部门、博物馆、非遗官方资料和可核对的出版物。每条事实记录标题、发布机构、日期、原链接、访问日期、支持的具体说法及可信范围；有起源争议时保留“传说/说法之一”，不要合并成确定历史。

将资料改写成每页约 60–120 字的短介绍，围绕“这是什么—怎样形成这种吃法—今天如何延续”组织，关联到实际食物、旧物或空间变化。每页标明文化资料、虚构对白或场景观察；资料页提供可点击的特定来源。原文不要整篇搬运，也不要把店主的创作对白当史料。

## 六、每家店都重复执行的完成检查

1. 任意顺序从地图选择该店，步行路径不穿模，到达后的画面能看清人物和食物。
2. 文化页、出处和旧物特写可打开/关闭，不需要完成其他店才能体验。
3. 收藏、去重、移除、刷新恢复、返回该店和手册下载正确；未到访的店不假记成已看。
4. 昔日→今日→昔日均有完整翻墙，墙面、人物、陈设和 UI 同步；快速点击、暂停环境动态后仍能稳定。
5. 嘴型与眨眼连续，人物不跳位；蒸汽动态可见、无方形边、无穿模。
6. 手机竖屏下圆点命中、食篮开合、阅读滚动、页面按钮可达，没有水平溢出。
7. 运行 `npm.cmd test`、`npm.cmd run build`。扩展 `verify-explore.cjs` 覆盖新店，保留 `verify-street.cjs` 对林记/旧入口的回归；必要时更新断言以反映确实实现的新店数，不要删掉有价值的失败检查。
8. 留下真实浏览器截图、报告和未完成项，然后提交一个范围清楚的版本。不要把构建成功或 HTTP 200 当成视觉验收完成。
